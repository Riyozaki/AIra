# AIra — исследование архитектуры для локального ИИ

Цель: архитектура, которая **на единицу энергии решает больше задач** и работает
на телефоне/ноутбуке. Не «обогнать frontier по бенчмаркам».

## Структура

```
docs/00-research-framework.md   метод, метрики, воронка экспериментов, границы модели
docs/01-design-space.md         оси дизайна и 7 открытых математических задач
docs/02-capacity-findings.md    S1: ёмкость фиксированного состояния (готово)
tools/cost_model.py             модель стоимости: 10³ вариантов за секунды
lab/capacity.py                 ёмкость памяти d×d: аналитика + численный эксперимент
hypotheses/                     реестр гипотез (claim / prediction / falsifier)
runs/                           выгрузки переборов (CSV)
```

## Быстрый старт

```bash
python3 tools/cost_model.py table  --device phone     # сравнение при ~1B параметров
python3 tools/cost_model.py sweep  --device phone     # перебор -> runs/design_space.csv
python3 tools/cost_model.py table  --device laptop --params 0.3
```

Устройства: `phone` (60 ГБ/с, 35 TOPS, 2 ГБ), `laptop` (200 ГБ/с, 100 TOPS, 8 ГБ),
`h100` (3350 ГБ/с, 1000 TOPS).

## Что модель уже показала (1B параметров, 4 бита, контекст 32K)

| Архитектура | RAM | ток/с | мДж/ток |
|---|---|---|---|
| MHA | 3.7 ГБ — не влезает | 14.7 | 78.9 |
| GQA | 1.3 ГБ | 36.0 | 30.6 |
| Гибрид 3:1 | 0.6 ГБ | 67.3 | 12.3 |
| state-based | 0.5 ГБ | 69.4 | 11.1 |

KV-кэш, а не FLOPs, определяет всё на длинном контексте. Битность даёт ещё ~2×.

## S1 закрыт (6 секунд на 2 ядрах, без GPU)

Ёмкость линейного состояния ≈ `min(d, ранг ключей)`, наклон log k / log d = 1.00.
Обычное линейное внимание (hebbian) использует лишь 0.125·d против 1.0·d
у оптимальной записи — то есть теряет 8× ёмкости бесплатно.
Подробности: `docs/02-capacity-findings.md`.

## Принцип

Перебор живёт в модели стоимости (секунды), GPU получают только выживших
(см. воронку S0–S5 в `docs/00`). Каждая гипотеза обязана иметь prediction
и falsifier до запуска.
