# 03. Тернарные веса: что именно мы проверяем и какой результат будет «да» или «нет»

Статус: **вывод до эксперимента**. Все числа здесь — **оценки**, если рядом не указано «измерено».
Основа — `01_cost_model.md` (§8: рычаг «b — биты весов»), пороги — `02_success_criteria.md` (G1.x).

## 1. Объект

Это QAT по схеме BitNet b1.58 (Ma et al., arXiv 2402.17764, препринт): латентные веса хранятся в fp32,
в прямом проходе используется

  W_q = α · clip(round(W/α), −1, 1),  α = mean|W|  (одна α на матрицу),

градиент проходит через STE (∂W_q/∂W := 1). Активации на входе каждой тернарной матрицы —
int8 absmax по токену. Embedding и выходная голова остаются fp, это часть цены, она учитывается ниже.
**Ничего нового здесь нет**: это известный метод, мы измеряем его цену в нашем режиме (малое N, байты, CPU).

## 2. Ось «размер»

Число параметров N = N_lin + N_emb. Здесь N_lin — тернарные матрицы, N_emb — fp-часть (вход 256·d и выход d·256).

- Референс: S_fp = 16·N бит (bf16 — формат инференса; обучение в fp32 этого не меняет).
- Тернарная модель: S_t = b_t·N_lin + 16·N_emb, где b_t = 1.6 бит (5 тритов в байте, 3⁵ = 243 ≤ 256) против теоретических log₂3 = 1.585.

**Эффективное число параметров.** Тернарная модель с N_t параметрами имеет то же качество, что fp-модель с
N_eff = c·N_t параметрами, где 0 < c ≤ 1. Ту же форму используют Kumar et al., «Scaling Laws for Precision»,
arXiv 2411.04330 (ссылка по памяти, в этом ходе **не перепроверена**). Значение c зависит от N, D и рецепта; именно его мы измеряем.

Условие равного качества: N_t = N_fp / c. Тогда, пренебрегая N_emb (сколько это стоит — ниже):

  **k_size = 16·N_fp / (1.6·N_fp/c) = 10·c.**

С учётом fp-эмбеддингов:

  k_size = 16 / (1.6·(1−e)/c + 16·e'),

где e — доля N_emb в N_t, e' = N_emb/N_fp. На байтах (V = 256) при d = 256 и 4 слоях e ≈ 4% (оценка),
а при e = 4% член 16·e' съедает до половины выигрыша. **На малом N это вносит реальный вклад**,
поэтому в отчёте k_size будет считаться по точной формуле, а не по 10·c.

Связь с порогами (без эмбеддингов):

- G1.1 (k ≥ 5) ⇔ **c ≥ 0.5**;
- нижняя граница ДИ ≥ 3 ⇔ c ≥ 0.3.

### 2a. Против какого базлайна считать k_size (важно для честности)

bf16 — **слабый** базлайн для оси «размер». На практике fp-модель после обучения квантуют без дообучения (PTQ):
int8 или int4 с групповым масштабом (форматы вида Q8_0 / Q4_0 в llama.cpp, ≈ 8.5 / 4.5 бит на вес с учётом масштабов).
На больших N это почти без потерь (не проверено нами), на малом N потери могут быть заметны — их надо **измерить**.

Тогда честный множитель:

  k_size(vs PTQ-b) = b_eff · N_fp(b) / (1.6 · N_t),

где N_fp(b) — наименьшая fp-модель, которая **после PTQ до b бит** имеет то же качество, что тернарная.

- Против int4 (b_eff ≈ 4.5): потолок ≈ 2.8·c'.
- Против int8: ≈ 5.3·c'.

Здесь c' учитывает и потерю PTQ. **Это значит, что одна тернарность почти наверняка не даёт ×5 по размеру против сильного базлайна.**
×5–10 возможен только при перемножении с другими рычагами (`01` §8).

Отчёт будет содержать обе цифры: против bf16 (как в литературе) и против лучшего PTQ (как требует `02` п.6).

## 3. Ось «инференс на CPU» (декод, B = 1)

По `01` §3 декод упирается в bandwidth: t_tok ≈ b_tok/β, а b_tok ∝ S. Тогда

  k_dec ≈ k_size · η,

где η = (эффективная bandwidth LUT- или VNNI-ядра) / (эффективная bandwidth bf16- или fp32-GEMV). Это отношение не обязано быть равно 1:
распаковка тритов стоит ALU-операций. T-MAC (2407.00088) сообщает, что ядро упирается в память, но это **не проверено у нас**.
Значит, k_dec обязательно измеряется отдельно: сначала ядро, потом модель целиком.

## 4. Ось «обучение» — здесь тернарность не выигрывает

При QAT с латентными fp32-весами FLOPs шага ≈ 6·N·D, как у fp, плюс O(N) на квантование.
Для того же качества нужно N_t = N_fp/c, поэтому

  **k_train ≈ c ≤ 1**, то есть по стоимости обучения это **проигрыш**, а не выигрыш.

Отсюда честная постановка: тернарность — рычаг для осей «размер» и «инференс». По оси «обучение» она бесплатна,
только если c ≈ 1, иначе стоит 1/c. Ось 2 (стоимость обучения) придётся закрывать другими рычагами
(данные, условные вычисления, см. `00` §14).

## 5. Что известно из литературы (оценка ожидаемого c)

- BitNet b1.58 (2402.17764, [P]): паритет с fp16 LLaMA заявлен с ~3B. На 700M–1.3B есть разрыв в perplexity.
- TriLM / Spectra (2407.12327, [P]): разрыв уменьшается с ростом N (по памяти, **не перепроверено** в этом ходе).

Значит, на N ~ 1–10M (наш режим) ожидаемо c < 1. Насколько меньше, не знаю, отсюда эксперимент.
Гипотеза H-T1: c ∈ [0.3, 0.6] на N ~ 1–5M — это **гипотеза**, а не оценка из литературы.

## 6. Как измеряется c (до запуска)

1. FP-модели трёх размеров N₁ < N₂ < N₃. Тот же рецепт, то же число токенов D, valid bpb. Точки (log N, bpb) соединяются кусочно-линейно.
   Экстраполяция за пределы диапазона запрещена: если тернарная модель хуже самой малой fp, пишем «c < N₁/N_t», без точного числа.
2. Тернарные модели тех же размеров, тот же D. c(N) = N_fp^{-1}(bpb_t(N)) / N.
3. Равный бюджет тюнинга: для каждой ветки берётся сетка из 3 LR, выбор по valid. Известно, что BitNet любит больший LR, поэтому сетки сдвинуты по вариантам.
4. Seeds: пилот — 1 seed, без права делать выводы для G1. Зачётный прогон — ≥3 seed, ДИ по t-распределению.
5. Равенство D означает равенство train-FLOPs при равном N, но не при равном качестве: это фиксируется в отчёте (§4).

## 7. Что будет считаться отрицательным результатом

- c < 0.3 на всех N → по размеру G1.1 недостижим одной тернарностью при малом N. Это **не** опровергает литературу на больших N,
  но в песочнице доказать нельзя. Действие: перейти к приоритету №2 (хеш-память) и вернуться к тернарности на Kaggle (фаза 2).
- c растёт с N (наклон > 0) — это аргумент «за» (G1.3), даже если на малом N значение c низкое.
