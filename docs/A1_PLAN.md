## 0. Зачем этот документ (мотивация из измерений, не из вкусов)

Toy-стенд G0S закрыт собственной кил-клаусулой S-9a: на 9×9-Sudoku с нуля ни один рецепт
не поставил петельный механизм — НО при базовом acc ≤0.25 (недоучивание-маска, вердикт
«НЕ РЕШЁН», см. G0S_RESULTS §2, LK-1). Рабочая гипотеза проекта после сопоставления с
внешними данными: **петельная выгода стоит на предобученных представлениях**
(Retrofit-RD положителен на 0.5B-доноре при 759/768 понуждённой глубины; Parcae/Loopie/Huginn
положительны на претрен-шкале; наш toy отрицателен только в условиях «с нуля»).
Следствие: верификация оси «петли» на нашем железе возможна только через A1-ретрофит.
Этот документ фиксирует, КАК именно, с какими числами, и что убивает идею.

## 2. Архитектура вставки (patched, не «поверх»)

Паттерн Retrofit-RD, но с **нашим ядром D-002 вместо их sum-loop** — это главное отличие
плана от слепой реплики и наша страховка от их же болезни:

```
x̃⁽⁰⁾ = x_l  (скрытое состояние после слоя l донора, l выбирается середина: l = 12 для 0.5B)
для k = 1..K:
    x̃⁽ᵏ⁾ = LN_s(x̃⁽ᵏ⁻¹⁾ + β·LoopBlock(x̃⁽ᵏ⁻¹⁾; Θ_loop))     # D-002: связанное ядро, affine=False LN
x_l ← x̃⁽ᴷ⁾;  дальше слои донора l+1..L без изменений
```

- **LoopBlock** = полный transformer-блок той же ширины d=896: self-attn (GQA-схема донора,
  свои RoPE) + SwiGLU MLP с ratio донора, pre-RMSNorm внутри блока. Инициализация:
  **копией весов слоя l+1 донора** (не случайная — Retrofit показал: init из соседнего слоя
  ускоряет схождение и уменьшает просадку; это их Appendix-D приём, берём).
- **β = 1/4** старт (по TW-опыту: при LN_s масштаб β не критичен для связанности, но
  β≤0.5 держит λ̂_dir подальше от 1; β обучаема, скаляр, init 0.25).
- **LN_s** — LayerNorm без аффина над потоком состояния (D-002, «закон ограниченных контуров»:
  НИ ОДИН контур проекта не остаётся без ограничивающего; sum-петля Retrofit/DeepLoop — их
  боль, у нас запрещена TW-1).
- **Глубинная эмбеддинга k НЕТ** (TW-1c: не влияет, лишний параметр поверхностного порядка).
- Параметры патча = один блок донора: **14.9M** (attn 1.84M при GQA 14/2 + SwiGLU 13.07M
  + β; арифметика проверена кодом `lab/donor_patch.py`) + LN_s без аффина — в бюджет
  дообучения входит легко; модель после патча 494M + 14.9M = 508.9M.
- **Δt-контур:** в A1 НЕТ (R3: slow-канал не продан на задачах без предсказуемого медленного
  состояния; T4 открыта и паркована до иерархического домена). Документ фиксирует: двушкальность
  — отдельный ADR после A1.

## 3. Диета глубины (актив недели №1 — обязательный хвост)

G0S S-4/S-8a измерили: uniform[2,12] дал дрейф acc@64−acc@16 = **−13.7 п.п.**, lognorm с хвостом
до 32 — **−2.7 п.п.** (×5 подавление). Совпадает с выбором Huginn (lognormal) и
Parcae (per-sample sampling). Поэтому фиксируем:

- **K_train ~ LogNormal(μ=ln 4.5, σ=0.9), клип [2, 64]** (хвост длиннее G0S — под K_eval=64…128),
  per-sample (не per-batch — Parcae указали per-batch слабее).
- **K_eval ∈ {1, 4, 16, 64}** снимается всегда; дрейф acc(K) — телеметрия D-обязательная.
- Deep supervision: лосс на КАЖДОМ k с экспоненциальным весом w_k = γ^(K−k), γ=1.0
  (TW-4: формула Parcae Table 11 γ≈1.17–1.19 ≈ 1 в пределах их же шума; плоские веса — дефолт,
  γ-скан отложен до A1b).
- **Промежуточные/волновые подписи: ЗАПРЕЩЕНЫ на A1a** (G0S S-9: без базового качества они
  не ставят механизм; Retrofit-эффект = надзор НА доноре, а не с нуля). Термин «wave supervision»
  переносится в бэклог A1c как возможный усилитель после зелёной A1a.

## 4. Критик / halting — слушаем TO-3 (риск HIGH, путь per-token)

Внешний негатив недели (Retrofit-RD Appendix): на замороженном N24 supervised halting-head дал
9.11%, PonderNet-цель коллапсировала в always-max (Spearman=0). Вердикт: **pooled-state голова
останова — мёртвый путь**. Дизайн критика A1:

1. **Per-token информационный путь:** критик читает НЕ pooled состояние, а лёгкий сводку по
   токенам (top-κ по норме |x̃⁽ᵏ⁾−x̃⁽ᵏ⁻¹⁾| + низкопроходной pooled) — голова ширины d→256→1.
2. **Сигнал λ(x)/q(x) обучается distillation-целью:** эмпирический прирост качества токена
   от петли k→k+1 на обучающих батчах (deep-supervision уже даёт per-k лоссы — критик
   учится их предсказывать ДО исполнения петли). Никаких PonderNet-целей.
3. Полная схема σ‑δ по L1_SPEC §61: рабочее λ̂=0.75, θ калибруется на валидации, не в лоссе.
4. Порог для «адаптивность есть» (A1c): Spearman(ŷ_крит, d*/эмпирический выигрыш) ≥ 0.3 на
   валидации при фиксированном бюджете. До этого — статические K с диетой.

## 6. Замороженные предсказания A1 (кил-критерии при каждом)

- **AX-1 (identity-proxy):** при K=1 патч сохраняет ppl донора в пределах **±3%** на валидации
  дообучающей смеси после 0 шагов дообучения (init=копия слоя) и после 200 шагов.
  *KIL: просадка >5% после 200 шагов → identity-init вранье, ревизия патча один раз.*
- **AX-2 (ось качества):** по K_eval=16 acc/EM на верифицируемом домене (GSM8K-держатель)
  PATCHED > CONTROL (compute-matched двойник) на ≥3 п.п. при равных токенах дообучения.
  *KIL: две независимые попытки без выигрыша → ось «петли на доноре» для нас закрыта, pivot
  по RESEARCH §8 (SLM с нашей рецептурой/дистилляцией).*
- **AX-3 (связанность живёт на претрен-шкале):** λ̂_dir(K≤64) ≤ 0.85 на претронутом патче,
  d_norm(k) геометрически спадает; ноль NaN/overflow при K=64 fp16 (мы — fp32 master weights).
  *KIL: λ̂>0.95 после полного A1a → LN_s не масштабируется на рельный LM, D-002 под ревизией.*
- **AX-4 (K-диета переносится):** дрейф acc@64−acc@16 ≥ −5 п.п. на lognorm-хвосте [2,64].
  *KIL: < −10 п.п. при исполненной диете → хвост не панацея на LM-шкале, ревизия диеты.*
- **AX-5 (критик, A1c):** Spearman ≥ 0.3 (§4.4). *KIL: <0.1 двумя путями → T3/TO-3 закрывается
  в пользу статических K + внешнего верификатора.*

Протокольная гигиена: предсказания заморожены этим коммитом; addenda — только новыми
документами (как G0S_S8..S11), правки старых запрещены; вердикты пишутся как-есть
(fail-as-written легитимен).

## 7. Стыковка с воротами и рисками

- A1 — исполнение **G0→G1** по RESEARCH §8: AX-1..AX-4 = детализация строки G0/G1,
  AX-5 = подготовка T3. Итог недели на железе = строка scoreboard (C1/C6 patched-vs-control),
  не отчёт.
- Риск «потолок донора» (RESEARCH §536): смягчение — донор 2026-полки + контроль-двойник;
  если PATCHED≈CONTROL=потолок — это ответ «ось не про нас», а не провал инженерии.
- Риск HW-0: весь A1 на 0.5B в fp16+грэд-чекпоинт укладывается в 24 ГБ VRAM; CPU-инференс
  результата патча (инвариант HW-0) — не затронут: +9.7M параметров на токен-прогон.
- **TW-H остаётся открытым:** λ̂ на Huginn-3.5B весах — измерение на T0, один час, даёт
  независимую калибровку λ̂ до наших тренировок.
