# CDEMO_ADDENDUM_4 — R5: изоляция оси глубины (AB-маска: слоты не видят слоты)

**Дата: 2026-08-24, до прогонов R5. Родители: PROTOCOL + ADDENDA 1–3. R4 исполнен,
числа зафиксированы в results/cdemo/chain_r4.json и войдут в CDEMO_RESULTS как-есть.**

## 1. Зачем R5 (что показал R4)

R4 (регистровая задача, слоты видят друг друга) выучен всеми плечами и дал чистые
диагностики (Lsum λ̂=1.248≈1+β точно по TW-1; stop-rule на Lsum коллапсирует в
always-max — зеркало PonderNet-негатива Retrofit), НО главный вопрос он решить не может:
**токен-ось (CoT по слотам) всем доступна, поэтому реальный вклад оси глубины в обучение
не измерим** — все решают «по токенам», петля остаётся одним из способов.

R5 запрещает слотам читать слоты (AB-маска: для query i ≥ HEAD заблокированы все
ключи j ≥ HEAD; чтение x из позиции 0 разрешено). После этого единственный путь
значения σ^h(x) в слот h — **ось глубины**: слои (dense) или петли (loop). Лимиты по
построению: D2 ≤ 2 композиции, D8 ≤ 8, L ≤ K. Это и есть честный стенд «глубина как
вычислительный ресурс», чего R4 не мог дать.

Технически: опциональный block_mask добавляется в SharedCore/TinyLoopLM (models.py,
обратная совместимость — все стамые стенды не трогаются) и в DenseBlock/DenseLM.

## 2. Замороженные предсказания R5 (кил-критерии при каждом)

- **PC-8R.** L_ab: acc12@K16 ≥ 0.90. *KIL: < 0.50 → shared-core не умеет композицию
  σ по оси глубины даже здесь; тезис петель ограничивается drift-защитой.*
- **PC-9R (валидность изоляции).** D2_ab: acc(h≥5) ≤ 0.10; D8_ab: acc(h∈[9,12]) ≤ 0.20.
  *KIL: D2_ab(h≥5) > 0.50 → маска дырявая/токен-ось протекает, весь R5 невалиден.*
- **PC-10R (заголовок).** FLOPs до порога acc(h≤8) ≥ 0.80: L_ab ≤ 0.5 × D8_ab.
  Обоснование ожидания: D8 вынужден выучить одну и ту же σ в КАЖДОМ из 8 несвязанных
  слоёв (8× параметров и сигнала на ту же биграмму); L учит её один раз.
  *KIL: L_ab дороже D8_ab по FLOPs (>1×) → экономия петель не подтверждена и на
  depth-forced задаче; заголовок «обучаем быстрее» снимается.*
- **PC-11R (экстраполяция).** h∈[13,20] @K=32: оракул-чтение (ответ существует в
  каком-либо слоте) ≥ 0.50 для L_ab; strict-чтение слота h — репортится отдельно
  (структурный барьер: слоты 13..20 в train не получали лосса).
  *KIL: оракул < 0.25 → ось K не продлевает вычисление дальше train-диеты.*
- **PC-12R (сигнал критика, фидер T3).** На L_ab: Spearman(K_stop(σ-правило), h) ≥ 0.5,
  K̄_stop ≤ 8, падение acc от останова ≤ 2 п.п. *KIL: Spearman < 0.2 → внутренний
  сигнал глубины не читается из состояния даже на чистой задаче; TO-3 → блокер A1c.*
