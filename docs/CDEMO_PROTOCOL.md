# CDEMO_PROTOCOL — концепт-демо: петли как ось вычисления, измеренная в разах

**Дата заморозки: 2026-08-24, ДО прогонов.** Статус: исполняется на sandbox (2 CPU), без железа.
Ответ на постановку: до покупки железа должен существовать артефакт «вот алгоритм, вот
задача, вот измеренная кратность». Этот протокол — такой артефакт. Правило прежнее:
каждое предсказание PC-X несёт кил-критерий, вердикт пишется как-есть, fail-as-written легитимен.

## 0. Что доказываем (одна фраза)

**На задаче с доказуемой последовательной глубиной контур с общими весами обучается до
заданной точности дешевле dense-близнеца в измеримое число раз, а связанное ядро (D-002)
покупает тест-тайм глубину без переобучения.** Это и есть «обучать быстрее в столько-то
раз» в честной форме: FLOPs-обучения до порога точности + параметры + стоимость инференса.

## 1. Задача — итерация перестановки (ground-truth глубина = h)

- Узлы: n=32. Батч-сэмпл: случайная перестановка π ∈ S_32, старт x, глубина h ~U{1..12}.
- Последовательность: [π(1)..π(32), SEP, x] → ответ π^h(x), лосс только на ответе.
- Почему lookup не жульничает (урок TW-A1/G0S): ответ требует РОВНО h последовательных
  применений π; фан-ин обманки = n^h вариантов → ширина не покупает глубину (обратная проверка
  заложена в PC-2: dense-2-слой обязан провалиться на h≥5).
- Валидация: свежие π (генерализация по перестановкам, запоминание невозможно), 512 сэмплов.
- Почему задача валидна после G0S: базовое качество ДОСТИЖИМО на 2 CPU (элементарный шаг =
  табличный lookup, уже выучивался в TW-стенде за ~1400 шагов), и глубина не фейкуется шириной.

## 2. Плечи (все d=96, ff=384, 4 головы, одинаковая геометрия блока)

| плечо | весов на блок | блоков на токен (train/eval) | параметры |
|---|---|---|---|
| **L** (petля, D-002 ln-ядро, K~LogNorm(ln4.5,σ0.9)∩[2,16]) | общие | K̄≈5.5 train / ≤16 eval | ≈120K |
| **Lsum** (абляция: sum-ядро β=0.25 БЕЗ LN — ядро TW-1) | общие | то же | ≈120K |
| **D8** (dense-близнец, 8 несвязанных блоков) | ×8 | 8 | ≈880K |
| **D2** (dense-мини, по ширине ≥ петли) | ×2 | 2 | ≈220K |

Обучение: AdamW lr 3e-3, косинус, warmup 100, B=32, шаги 3000, deep supervision на всех k
(L-плечи), обычный лосс (D-плечи). Железомерные единицы: шаги, секунды (то же железо),
условные FLOPs = шаги × блоков-на-токен × B.

## 3. Замороженные предсказания (кил-критерии при каждом)

- **PC-1 (базовая решаемость).** L: acc(h≤12) ≥ 0.85 к шагу 3000 при K_eval=16.
  *KIL: acc < 0.5 → окружение sandbox не тянет и эту задачу; концепт-демо масштабируется
  до железа, toy-с-нуля закрывается окончательно.*
- **PC-2 (глубина не покупается шириной).** D2: acc(h≥5) ≤ 0.35 при любых acc(h=1).
  *KIL: D2 acc(h≥5) > 0.70 → задача фейкуется lookup-фан-ином, вся демка невалидна,
  задачу заменить (revise-once).*
- **PC-3 (КРАТНОСТЬ ОБУЧЕНИЯ — заголовок).** FLOPs-обучения до acc(h≤8) ≥ 0.80:
  L ≤ 0.5 × D8 (т.е. **не менее чем ×2 быстрее** по вычислениям на том же железе;
  ожидание по диете K̄≈5.5 и равной скорости сходимости: ~×2.5–3.5).
  *KIL: L медленнее D8 по FLOPs → тезис «обучать быстрее» снимается с табло, остаётся
  только параметрическая экономия (слабая версия).*
- **PC-4 (тест-тайм глубина без переобучения).** L, обученная с хвостом ≤16, при K_eval=32
  на невиданном диапазоне h∈[13,24]: acc ≥ 0.50. У D8 этого рычага нет по построению.
  *KIL: acc < 0.25 → λ̂-закон не держит экстраполяцию на своей же задаче; T1′ под ревизией.*
- **PC-5 (σ-правило останова, первый замер на решающем стенде).** Стоп
  d_k < 0.05·d_1: средний K̄_stop ≤ 8 при падении acc ≤ 2 п.п. относительно K=16 (ожидание:
  экономия инференса ×2–3 на смеси лёгких/трудных; λ̂≈0.5–0.8 → геометрию видно по d_k).
  *KIL: падение > 5 п.п. или K̄_stop ≥ 12 → σ-правило не работает без критика; критик
  становится единственным путём (поднимает приоритет TO-3 до блокера A1c).*
- **PC-6 (LN-ядро — несущая причина).** Дрейф acc@(K=32)−acc@(K=16): L ≥ −3 п.п.,
  Lsum ≤ −10 п.п. (или смерть по нормe). *KIL: Lsum ≈ L → bounded-ядро не является
  причиной тест-тайм глубины; D-002 теряет статус «несущего» и понижается до «одного из».*
- **PC-7 (калибровка метрики на решающем стенде).** λ̂_row(L после обучения) ∈ [0.4, 0.85],
  r² ≥ 0.8 — закрывает «заметку №2» (λ̂ валиден только на связанном+решающем стенде).
