# G0S_S9 — протокольное дополнение: волновой надзор (Retrofit-style, B3)
Дата: 2026-08-24. Заморожено до запуска варианта `ln_big_wave`.

## Основание
Retrofit-RD (2608.11233): промежуточный надзор «один шаг задачи на петлю» устанавливает
переиспользуемый механизм (84% vs 72% против токен-CoT контроля), подписи по глубине — ключ.
Наш стенд имеет граунд-трут волновой индекс каждой клетки w_c (волна, в которой клетка
становится форсированной) → прямая реализация того же принципа на земле истины.

## Вариант ln_big_wave
Архитектура/диета как `ln_big` (S-8: d=96/384, lognorm K). Отличие одно: лосс на петле k —
CE только по клеткам с w_c ≤ k (маской; прочие игнорируются). Петля k обязана отвечать за
состояние доски после волны k — никаких «решил на k=1 и застыл». Бюджет идентичен (3500 шагов).

## Предсказания S-9 (до запуска; кил-критерии)
- **S-9a (механизм устанавливается):** acc_blank@16 − acc_blank@1 ≥ +15 п.п. агрегатно,
  deep gap ≥ +20 п.п. Иначе — сильный негатив всей ставке латентных петель на toy-шкале:
  даже прямой волновой надзор не делает петли вычислением. Тогда запись в реестр: toy-шкала
  латентных петель признаётся непригодной для верификации; верификация переносится сразу на
  ретрофит донора (A1-путь), toy-стенд пенсионеруется.
- **S-9b (градация по глубине задачи):** Spearman(τ_stab, d*) ≥ 0.5, медианы deep/shallow ≥ 1.5
  (условие сигнала глубины для критика — S-3, отложенное из-за неиспользующих петли бейзлайнов).
- **S-9c (перенос волны → ответ):** acc_blank@K где K≈median d*+2 ≥ 0.55, и/или точность
  волновых промежуточных отметок `wave-acc` (клетки своей волны) ≥ 0.7 — любая из двух =
  механизм внутри, даже если финальный acc урезан диетой.
- Отрицательная фиксация заранее: если S-9a проходит, а S-9b нет — механизм есть, но его
  внутренние часы не линейны по w_c; критик тогда дизайнится на wave-acc сигнале, не на τ.
