## 1. Уровни событий и что точно входит в L1

Событийность существует на четырёх шкалах; два верхних уровня уже в плане без L1,
скалярный запрещён контрактом. L1 = **E1 + E2 внутри петель рекуррентного ядра**.

| Уровень | Гранулярность | Что пропускаем | Статус |
|---|---|---|---|
| E0 | весь запрос | лёгкие запросы целиком (K̄(x) малое) | в плане: роутер+критик (T3) |
| E1 | **целый слой петли** | дельта-слой ≈ 0 на поздних петлях | **L1** |
| E2 | **блок каналов FFN (64–512)** | колонки/строки W_up/W_down неактивных каналов | **L1** |
| E2b | отдельные головы GDN | обновления малых β-голов | опционально, фаза 2 |
| E3 | скалярные каналы | — | запрещено (дивергенция, C4-налог) |

Почему не события «между токенов» (кэш активаций): attention-смешивание делает
«неизменность» между токенами ложной почти всегда; там уже работают обычные механизмы
(KV-кэш/состояния GDN). Наш сайт — **ось петель**, где изменение по построению монотонно
затухает (лемма T1), и где живёт главная цена модели (K-проходы ядра).

## 2. Математика

### 2.1. Оператор заморозки [Т-постановка]

Точный шаг петли:  z^k = F(z^{k−1}),  F — λ-сжа́тие (ассумпция T1, измеряется P-01).
Декомпозиция по блокам z = (z_1..z_G). Событийный шаг:

```
z̃^k = z̃^{k−1} + M_k ⊙ (F(z̃^{k−1}) − z̃^{k−1}),     M_k ∈ {0,1}^G (маска событий)
вливаемая ошибка шага:  e_k = (1−M_k) ⊙ (F(z̃^{k−1}) − z̃^{k−1})
‖e_k‖ ≤ ( Σ_{b: заморожен} Δ_b² )^{1/2},   Δ_b ≡ ‖F_b(z̃^{k−1}) − z̃_b^{k−1}‖
```

### 2.2. σ-δ долг-планировщик (ядро идеи) [М]

Для каждого блока ведётся **долг обновления** D_b — дисконтированная оценка накопленного
пропущенного изменения:

```
D_b ← λ̂·D_b + Δ̂_b      после каждой петли;   сброс D_b ← 0 при событии блока

[ИЗМ. 2026-08-24, T-неделя]: λ̂ осмыслен только на стабилизированном ядре. Измерено:
sum-ядро EXP навсегда (λ=1+β, обучением не лечится — TWEEK_RESULTS §R1); ln-ядро λ̂_dir≈0.59.
Рабочее λ̂ = 0.75 (THEORY T1′). Все расчёты PB-01..PB-04 исполняются на ln-ядре (D-002).
событие b на шаге k  ⟺  D_b ≥ θ_b
```

Ключевой дизайн-выбор (не эстетика): **дисконт долга равен самому λ̂** — пропущенное
изменение «смывается» ровно с той скоростью, с какой петля сама забывает свои старые
ошибки (контракция). Это делает долг калиброванным в единицах остаточной ошибки T8 и
превращает порог θ_b в апостериорный бюджет ошибки, а не в подкручиваемый knob.
Δ̂_b — прогноз очередного изменения без его вычисления; варианты — §3, решение — бейк-офф PB-02.

### 2.3. Граница (обобщение T8 на маски) [Т-скетч]

По индукции из T1: ‖z̃_K − z_K*‖ ≤ λ^K‖z_0−z*‖ + Σ_{j=1..K} λ^{K−j}‖e_j‖.
Если аллокация порогов гарантирует ‖e_j‖ ≤ ‖θ‖₂ (по построению планировщика, см. 2.4), то

```
E_add ≡ ‖z̃_K − z_K^(точн.)‖ ≤ ‖θ‖₂ · (1−λ^K)/(1−λ) ≤ ‖θ‖₂ /(1−λ)
```

— та же форма, что у T8 (λθ/(1−λ) для полной остановки), вместо фактора λ — накопление
за весь хвост петель. **Читательская формула:** при λ̂=0.72 полная остановка по θ даёт
запас ×2.6θ; событийная заморозка на протяжении сходимости — до ×3.6θ. За право
экономить на всём хвосте платим коэффициентом ~1.4 к бюджету ошибки. Это и есть честная
цена событийности, предсказанная до эксперимента (проверка — PB-03).

### 2.4. Аллокация порогов [Т/инженерное правило]

Задача: максимум сэкономленной работы Σ_b (skip_b·cost_b) при бюджете ‖θ‖₂ ≤ ε*·(1−λ̂).
Равномерные блоки и цены ⇒ θ_b = θ единый; блоки разного масштаба ‖z_b‖ (слои с разной
энергией) ⇒ **θ_b ∝ s_b**, где s_b — скользящий масштаб ‖Δz_b‖ (водоналивание по шуму:
доводим каждый блок до одинаковой ОТНОСИТЕЛЬНОЙ ошибки). Предсказание Pθ: измеренные
оптимумы θ_b на dev лягут на прямую θ_b/s_b ≈ const (отклонение >2× — главу править).

### 2.5. Совместная формула цены (весь стек в одну строку)

```
Цена(ответ) ≈ P_active · 2 · E[K̄(x)] · ( ᾱ_mix + ᾱ_FFN·β̄ ) · price_op + C_critic
              роутер T3 ───┘        └─ события E1 (β̄) и E2 (ᾱ) ─┘          └ ~1–3%
```

Мечта-фактор L1 — загнать (ᾱ, β̄) к 0.3–0.5 при заданной точности: ×1.6–2.2 от стоимости
петли, мультипликативно к роутеру K̄(x) (который сам даёт ×4 по Snell-литературе).

## 3. Варианты предсказателя Δ̂ (бейк-офф, обязателен бейзлайн D)

| Код | Предсказатель Δ̂_b | Цена | Гипотеза |
|---|---|---|---|
| A | моментум реализованных ‖Δz_b‖ прошлых петель | ~0 | простота; слеп к новым режимам x |
| B | линейная голова от (z̃_b^{k−1}, h_0) на обучении | <2% цены блока | точность + адаптивность к x |
| C | **σ-δ-долг (§2.2)** | ~0 + регистры | самокалибровка в единицах ошибки; естественная устойчивость к хвостам |
| D | статический TopK-предиктор в стиле Spark (8%-активность) | <2% | **чужой сильный бейзлайн — обязателен к включению** |

Правило приёма (честность-защита): если D на равном бюджете активности бьёт A/B/C по
качеству — слот НЕ умирает, но принимает D как планировщик, а «изобретением» остаётся
формализм границ из §2 (T8′, долг как бюджет ошибки). Изобретательская честь —
не заслонять стену телом.

## 4. Соседние работы и граница новизны (письменно, чтобы не врать себе)

- **CALM** (Schuster+, 2022): ранний выход по ТОКЕНУ с калиброванными порогами и
  провабельным контролем качества, до ×3. — это наш E0/E1-контрапункт для статичных
  сетей; их калибровку (S_cal) перенимаем как протокол подбора θ на dev.
- **LayerSkip** (Elhoushi+, 2024): обучение С ранними выходами (layer-dropout +
  early-exit loss) — наш шаблон фазы обучения под события (§5).
- **TIDE** (2026): потокенный выход, 98–99% токенов выходят рано без потери ответа —
  свидетельство, что глубина избыточна на большинстве токенов (косвенно за нас).
- **Spark Transformer** (2025): FFN-активационная разреженность из коробки обучения:
  8% активных каналов, FLOPs→40%, ×1.79 wall-clock на CPU, почти без потерь. Это наш
  конкурент-бейзлайн D и одновременно доказательство, что канальная событийность
  совместима с денс-ядрами.

**Граница нашей новизны (впишем в решение adopt):** (а) события живут ВНУТРИ
весо-связанных петель уточнения — замороженный блок просыпается позже, когда долг
переполнен (временна́я, а не статическая разреженность); (б) σ-δ-долг как
самокалиброванный бюджет ошибки с границей T8′ в терминах измеренного λ̂;
(в) композиция трёх шкал событий (E0 роутер × E1/E2 L1 × остановка T8) с одной
кумулятивной границей. Всё остальное — инженерная сборка, и мы так и напишем.

## 5. Обучение под события (фаза A чекпоинтов)

- **Случайная заморозка на тренировке** (по мотивам LayerSkip): на каждом развёрнутом
  шаге k блоки замораживаются стохастически так, чтобы средняя активность сходилась к
  расписанию ᾱ_target: 1.0 → 0.35 к концу фазы A. Глубокая супервизия (T-рецепт)
  здесь бесплатно помогает: промежуточные чтения головы не дают «спрятать работу»
  в замороженные хвосты.
- **Двойной режим потерь:** основной лосс считается на точных шагах (эталон), эвент-шаги
  — со штрафом-регуляризатором на близость к точным (KL между логитами точного и
  эвент-режима на одних и тех же позициях, вес 0.1–0.3, подбирается один раз).
- **Калибровка после обучения:** θ_b выбирается по dev так, чтобы измеренная активность
  α̂_b попала в коридор назначенный расписанием, И κ·‖θ‖₂/(1−λ̂) ≤ ε*, где ε* взято из
  кривой P-02 (шумовой пол). Один калибровочный прогон, не святая корова пересмотра.
- **PB-03-предсказание:** обученная-под-события сеть держит α до 0.30–0.50; пост-хок
  события на обычной сети — только до 0.70–0.80; разрыв — мера того, что даёт фаза A.

## 6. Инженерия (денс-совместимая, без экзотики)

- **Гранулярность:** блоки E2 — 128 каналов (коридор 64–512; g* из v2-формулы
  ln(1/α)/ρ при ρ≈10⁻² даёт порядок сотен — совпадает с SIMD×развёрткой 8×16).
  Для d_ff=2304: 18 блоков/слой ×8 слоёв = 144 юнита управления на петлю — оверхед
  планировщика <2% цены петли.
- **Ядра:** активные блоки собираются НЕ собранными scatter-масками, а **сплошными
  подрезками строк/столбцов** (планировщику разрешено переставлять каналы внутри
  блока при экспорте весов — пермутация каналов FFN эквивалентна сети; порядок
  «часто-активные вперёд»): sub-GEMM по непрерывным диапазонам, AVX2 для x86-64 и
  NEON для ARM64 (контракт HW-0), на GPU — grouped/block-sparse triton-ядро.
  Оверхед бюджет: ≤15% при активности ≥30% (проверка — микро-бенч в дни 1–3).
- **Память:** регистры долга D_b — 144×4 Б на петлю; ничтожно. Никаких новых
  структур данных (запрет на sparse-форматы — §0).
- **Режимы запуска:** `--events off | posthoc | trained` в конфиге среза модели;
  `off` — дефолт до PB ✓. Структурный вывод (JSON/tool-call/код-блоки) ВСЕГДА в
  точном режиме (наследуем правило v1 D-009: эвристика не меняет распределение
  протокольных токенов).
- **Защёлка эскалации:** критик T3 вправе форсировать полные точные петли на позициях
  с q̂ < θ_hard (напоминание: события — ускоритель уверенных ходов, не политика).

## 8. Расчётный пример (AS-0, 140M, d=768, 8 слоёв/петля)

Доли цены петли: FFN ~0.60, смесители+проекции ~0.40. Рабочие точки-предсказания:

| Режим | ᾱ_FFN (E2) | β̄ skip-слоёв (E1) | Экономия петли | Замечание |
|---|---|---|---|---|
| обученные события, точность-стража | 0.5 | 0.2 | ≈ 0.6·0.5+0.2 = 50% → ×2.0 | цель PB-01 |
| агрессивная | 0.35 | 0.3 | ≈ 69% → ×3.2 | просадку измерим; structured-out — off |
| пост-хок (без фазы A) | 0.75 | 0.1 | ≈ 25% → ×1.33 | ожидаемый «сюрприз-отрицатель» |

Совместно с роутером K̄: бытовой диалог (K̄=2)×(E2 0.5) ⇒ цена токена ≈ 0.5·2 = 1.0
базисных петли-токена против 8 у «думать-всегда-K̄8-точно» — совокупный множитель ~×8
к лобовой политике (до TTC-выбора), что и есть «мечта-фактор» слота, разложенный
по составителям честно.

## 9. Риски (по убыванию убийственности)

1. **Гейтер-налог:** срезанные GEMM малых ширин теряют эффективность (утил <15% пика) —
   микро-бенч в дни 1–3 решает раньше, чем потрачено; fallback: только E1 (пропуск
   слоёв — грубая, всегда выгодная гранулярность) с фактором ×1.3-1.5 в запасе.
2. **Хвост входов:** планировщик банкротится на редких режимах (редкие языки доменов,
   adversarial-формат) — страховка: критик-форс §6 + D-бейзлайн; политика «хуже контроля
   на срезе = события off по умолчанию для этого домена».
3. **Взаимодействие с квантизацией:** тернарная среда поднимает δ — долг честно
   перерастает порог чаще (λ̂ не меняется, но ε* уже занят шумом P-02) — отсюда порядок
   ворот: события доказываются ДО тернарки (G1→G3), перенос — только через PB-04.
4. **Нестабильность обучения фазы A:** ramp α 1.0→0.35 лечит; если нет — принимаем
   posthoc-режим с проигрышным фактором ×1.33 как «не слот, а бесплатную опцию», что
   тоже засчитывается результатом слота (не провалом).

## 11. Чем этот слот НЕ является (анти-соблазн, письменно)

Не SNN и не спайки (они в парке по налогу C4); не замена планировщику K̄(x) (водружён
ПОД ним, а не вместо); не «экономия в отчёте» — цена считается стеной на T1, а не
FLOP-экраном; не пятый повод переписать рантайм (всё — внутри стандартного ggml-файла
с двумя новыми операторами: slice-GEMM и debt-update).
