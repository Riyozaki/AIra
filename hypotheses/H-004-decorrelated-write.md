# H-004 — Декоррелирующая запись в состояние даёт ×4–8 ёмкости бесплатно

```yaml
id: H-004
status: screening (частично подтверждена аналитически)
cost: 0 GPU-часов на S1, 2 GPU-дня на S3
```

## claim

Замена аддитивной записи в состояние (hebbian, как в обычном линейном внимании)
на декоррелирующую (delta rule / least-squares) увеличивает число ассоциаций,
удерживаемых при cos ≥ 0.9, с ~0.125·d до ~1.0·d — **без роста байт и без роста FLOPs
на инференсе**.

## mechanism

Аддитивная запись суммирует вклады и оставляет перекрёстные помехи
(`k_j·k_i` для i≠j). Декоррелирующая запись вычитает проекцию нового ключа
на уже записанное, поэтому помехи гасятся. Матрица та же, меняется только правило.

## prediction

- S1 (сделано): ёмкость hebbian 0.125·d, lstsq 1.0·d при d = 32…256.
- S3: при равных параметрах и FLOPs модель с delta-записью должна показать
  ≤ −2% loss на задачах ассоциативного recall, и не хуже — на остальных.

## falsifier

Если на реальных данных (не гауссовых ключах) выигрыш < 0.5%, значит корреляция
ключей в языке съедает весь запас, и ось закрывается.

## известный риск

Delta rule за один проход страдает от эффекта недавности: на загрузке λ ≥ 1 он
хуже hebbian (0.676 против 0.711). Нужна нормировка или несколько проходов —
иначе выигрыш будет только на недогруженном состоянии. Замерено в `docs/02`.
