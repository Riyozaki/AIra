# FEATURES.md — разведка фичей чужих LLM-стеков → план переноса в LeanCore

Источники: Kimi Linear (arXiv 2510.26692), DeepSeek-V3 (arXiv 2412.19437), Qwen3 TR (arXiv 2505.09388),
Gemma 3/4 QAT-релизы (google), Anthropic Constitutional AI (2022+2026 spec), Muon (Keller Jordan, modded-nanogpt).

## Разобранные фичи и вердикты для нашей шкалы

| Фича (откуда) | Суть | Вердикт для LeanCore |
|---|---|---|
| **KDA — channel-wise decay + delta rule** (Kimi Linear) | Затухание по каналам (а не по головам) + delta-правило: состояние-матрица S, rank-1 коррекция `S ← Diag(α)S + β(v − Sᵀk)kᵀ` | **ПЕРЕНОСИМ**: у нас уже канальный α (как KDA), добавляем delta-правило (матричное состояние). Это прямой апгрейд нашего EMA-блока. Фича B. |
| Гибрид 3:1 (KDA:MLA) + NoPE (Kimi) | Глоб. attention раз в 4 слоя; поз-кодирование отдают линейному слою | У нас attention победил изо-цену ранее — гибрид противоречит нашей цели (поток без кэша). НЕ берём, но τ-гейт и pos — уже NoPE-совместимы. |
| **MTP multi-token prediction** (DeepSeek) | Доп. головы предсказывают t+2,...: плотнее сигнал обучения + спекулятивный дикод (85–90% accept на 2-м токене) | Спекуляция НЕ ускоряет RNN-стриминг (нет батча верификации). Имплементировано как обучающий сигнал (`--mtp`, FD-проверено); A/B ниже. |
| **Aux-loss-free MoE** (DeepSeek) | Эксперты с bias-коррекцией маршрутизатора вместо aux-loss; квантование активаций FP8 | **ПЕРЕНОСИМ top-1 MoE-FFN** (4 эксперта оф F/2, bias-баланс): меньше активных FLOP/токен. Фича C. |
| **Strong-to-weak distillation** (Qwen3) | Малые модели учатся на логиты больших; > RL по эффективности | **ПЕРЕНОСИМ**: champ4k → student (D=128, L=3): CE + KL(T=2). Ось сжатия с сохранением качества (та же цель, что Gemma-QAT). Фича E. |
| Thinking/non-thinking budget (Qwen3) | Переключение режима «думать»; бюджет токенов мышления | Прямого аналога нет (нет reasoning-данных). **Наш аналог — τ-гейт ADR: бюджет вычислений на токен** + бюджет max_tokens в обвязке. Документируем как соответствие. |
| **Gemma QAT рецепт** | ~5k шагов QAT-файнтюна с дистилляцией от fp32-чекпоинта; статичные скейлы активаций; выборочный 2-бит | У нас QAT-400 уже работает; добавляем: (а) QAT с KL-целью к fp32-учителю (= Gemma рецепт буквально), (б) опцию статичных скейлов активаций. Часть фичи D/E. |
| **Constitutional AI** (Anthropic) | Конституция → self-critique → revision → RLAIF | Напрямую для 2.6M-модели нереально (качество критика). Переносим **обвязочную часть**: файл-конституция как системный промпт + self-revise проход (draft→critique→revise) как протокол инференса. Фича A3. |
| **Muon optimizer** (KellerJordan) | Momentum + Newton–Schulz ортогонализация обновлений 2D-матриц; −35% времени обучения NanoGPT | **ПЕРЕНОСИМ**: Muon для 2D (Wm/fc1/fc2/E), Adam для скаляров/смещений. NS5 — numpy-реализация. A/B при равных шагах. Фича B2. |
| FP8 training (DeepSeek) | Смешанная точность | Не применимо в numpy-разведке; у нас QAT уже покрывает инференс-ось. [не берём] |
| MLA (латентное сжатие KV) | Для attention-кэша | Нет attention ⇒ не применимо. [не берём] |

## Промежуточные результаты (первая волна измерений)

- **Muon**: 600 шагов ema+ADR: **142.01 vs Adam 165.81** (−14.4% PPL при −8% wall) ⇒ **принят** (μ-lr=0.02).
- **MoE-FFN top-1 aux-free (E=4, F/2)**: 500 шагов, muon: **159.52 vs dense ~146** ⇒ **отклонён** на 2.6M-шкале (+34% параметров при худшем PPL; numpy-mask-оверхеды). Bias-баланс работал (uniform loads), но узких экспертов недостаточно.
- **QAT-KL (Gemma-рецепт: KL к fp32 + Muon)**: **125.62 vs 126.82 plain-QAT** ⇒ **принят**, стандарт QAT-стадии.
- **KDA-delta (k=v=self, без отдельных k-проекций/голов)**: с гейтом σ(xWg) обучение стабильно, но сходимость радикально медленнее EMA (~4300 PPL @250 шагов vs ~170 у ema) и плато ⇒ **[отрицательный на этой шкале/формулировке]**: полное KDA требует выделенных k/q-проекций + мультиголов + short-conv — цена параметров/вычислений ломает нашу изо-качественную рамку. Канальный decay (главная идея KDA) у нас уже есть в EMA.
- **MTP-aux (λ=0.1, t+2)**: 600 шагов muon: **142.26 vs 142.01** без MTP ⇒ разницы нет (нейтрально, +35% wall) ⇒ **[не принят]** как тренировочный буст на этом бюджете; оставлен для спекуляции в будущих задачах.
- **Обвязка**: chat-протокол, sampling, τ-live-budget, revise; HTTP сервис.

## Волна 3 (финал)
- **QAT-KL с правильным масштабом**: **124.27** (vs plain 126.82, vs noisy-KL 125.62) ⇒ KL-к-fp32 = стандарт QAT. Артефакт `results/champ4k_qat_kl.lcw2`: stream-PPL **108.56** (лучший).
- **Distill (CE+0.5·KL, T=2, студент 1.38M)**: 193.88 vs scratch 176.61 @400 ⇒ **[отрицательный на нашем бюджете]** (Qwen3-эффект проявляется на 36T-масштабе; у нас студенту выгоднее жёсткий CE).
- **champ-v2 (champ4krun +600 шагов Muon, lr 2e-4)**: 126.54 — bump от рестарта lr не компенсировался ⇒ чемпион остаётся champ4krun (123.30). Muon-сила проявляется с нуля (142.01 vs 165.81 @600).

## Волна 4 (мультипликативный ×10-стек)
- **Тренировка ×1.5 (2835→4293 tok/s, ppl на месте)**: профилировка показала gelu = 47% шага (pow(x,3) + ~12 точных проходов) — переписан слитым по памяти + EMA-скан переведён с Python-цикла 96 итераций на треугольные einsum-матрицы (fwd Σ_k a^{t−k}(1−a)x_k, bwd транспонированная матрица; градчек ALL PASS; ppl@59 380.16 vs 382.46 — в шуме).
- **Артефакт ×2.14 (5.76→2.69MB) без потерь**: `--share8` в экспортере — E в per-row int8 + f16-скейлы, голова читает ТЕ ЖЕ строки (E[v,:]==head col v); EtT-таблица удалена. Stream-PPL C-движка: **108.51 vs 108.56**; numpy-проверка эмбеддинга 101.32 vs 101.37. Ген: **6079 tok/s** (4737 до). ФИКС найденного бага приоритета операторов при чтении E.s.
- **Head screening (2-то уровневая частичная оценка) ⇒ [не принят]**: совпадение teacher-forced argmax 66–84% (SD16/K256 лучший = 83.6%) — для greedy недопустимо, для sampling деградирует; ускорение ×1.44 не стоит качества. Полная голова с int8-SIMD уже даёт 6000+ tok/s.

- **champion-3 (полный muon-прогон 2000 шагов на ускоренном тренере)**: fp32 **122.33** (vs 123.30 за 4000 — старый чемпион) → QAT-KL-400 **120.26** (vs 124.27) → экспорт share8 → **stream PPL 104.65** (было 108.51). Рекорд поднят на всех ступенях, артефакт `results/champ3_qat_kl8.lcw2` развёрнут на :8080.

- **Threads sweep**: OPENBLAS 1/2/4 → 3399/4293/4052 tok/s — ядро упёрлось в память, 2 потока оптимум (оставлено).
- **Остаточный план тренировки (если дожимать ×10)**: граф после оптимизаций = matmul-BLAS (пол, дальше только больше ячеек) + горячие elementwise (softmax_ce 13%, gelu ~14% после слияния, einsum-attn 6%) — следующий шаг это C-extend (ctypes) для softmax/gelu/layernorm: оценка ещё ×1.5–2. Дальше упор в BLAS-GEMM → нужен C++ dgemm-батчер. Текущий статус стека: training ×1.5 · footprint ×2.14 · gen ×1.28 = **≈×4.1 агрегатно при ПОВЫШЕНИИ качества** (122.33/120.26/104.65).

## План имплементации (каждая фича = измеримый A/B, отдельный коммит)

- **Фича A (обвязка)**: sampling в lc_stream (temp/top-k/top-p) + `lc_repl.py` (токенизатор из meta.json, интерактив, системный промпт/«конституция», бюджет токенов); service-mode по HTTP (один бинарник, OpenAI-подобный /v1/completions минимум).
- **Фича B (KDA-lite)**: `nano_kda.py` — delta-rule состояние (D×D) с канальным α; BPTT руками + gradcheck; A/B vs EMA при равном бюджете.
- **Фича B2 (Muon)**: `--opt muon` в тренере; A/B vs Adam при равных шагах.
- **Фича C (MoE)**: `nano_moe.py` — top-1 aux-loss-free FFN; PPL@step и tok/s обучения.
- **Фича D (MTP-aux)**: вторая голова t+2 (вес 0.1, shared E), измерение ΔPPL обучения.
- **Фича E (distill)**: champ4k → student 1.1M params, CE+KL, сравнение с from-scratch.

Каждая фича включается флагом и обязана пройти gradcheck/валидацию; отрицательные результаты фиксируются как раньше.
