### 3.4 kNN-память по скрытым состояниям (`lc_knn.py`) — [измерено] качественно ЖИВА, скоростно мертва
Самая сильная форма «триггерного всплытия»: ключ = полный z (192) после финального LN, datastore = 301k
позиций train (шаг 3), top-32 по косинусу, softmax по сходству с температурой, смесь с моделью
`p = (1−λ)·p_model + λ·p_knn`. Протокол честный: λ на val[:half], отчёт на val[half:].

| λ | PPL@cal | PPL@test |
|---|---:|---:|
| 0.00 | 200.88 | **200.17** (чистая модель) |
| 0.05 | 178.87 | 178.84 |
| 0.10 | 172.15 | 172.34 |
| **0.20** | **167.79** | **168.24** |
| 0.30 | 169.20 | 169.90 |
| 0.50 | 184.49 | 185.88 |

**−16% PPL при λ*≈0.2** [измерено, один чекпоинт]. Это первый ЖИВОЙ представитель семейства
«вспоминание по ключу» на нашем стеке. Но цена: retrieval (точный скан N=301k) = **6.07 мс/токен**
против 0.053 мс/токен у всей матричной головы — на два порядка дороже; потоковый инференс
(~0.29 мс/ток) рухнет до ~160 ток/с. Знакомая патология семейства: **fit есть, скорости нет**.
Выживание возможно только через приближённый поиск (HNSW/квантованные ключи), который сам начинает
напоминать «триггерную полку v2» и должен доказать сохранность λ*-выигрыша после потери recall —
это отдельный зонд, без гарантий. Прямой вывод: семейство НЕ отвергнуто по качеству, отвергнуто по
стоимости точного индекса; «триггер-only» сокращения (человеческая метафора «по ключевым триггерам»)
— это ровно этот компромисс «меньше ключа = больше дешевизны = меньше точности всплытия».

## 4. Что принимаем как процесс (из их комплекта безопасности)

1. **Любой «бypass/событийный» механизм** доказывается только: proper-mixture PPL + замеренные tok/s + importance-sampled оценка стоимости — запрет на псевдо-метрики.
2. **Калибровка порогов** — только на отложенной половине валидации, отчёт на второй половине (Wilson-LB, поддержка n; воспроизведено в `lc_shelf.py`).
3. **Мягкие веса** вместо жёсткой фильтрации данных (floor 0.10–0.20), если когда-либо вернёмся к novelty-весам.
4. **Гейты**: burst/per-cycle лимиты на «дешёвое плечо», мониторинг дрейфа калибровки между доменами (их cross-domain дрейф = наша потенциальная prep5k/prep6k).
5. Новые эксперименты — фиксация отрицательных результатов обязательна (эта традиция уже есть в наших wave-доках).

## 5. Остаточные гипотезы (парковка, без бюджета)

- Многотокенный «jump head» поверх потока (их оракул-граница ×7.88 на байтах) — у нас RNN не проверяет спаны дёшево; ждёт появления span-verifier-а.
- Эпизодика-по-сюрпризу (HDC, чтение 4.2%) — только для дистанционного повтора фактов; на нашем корпусе 1M токенов — сигнал подозрителен; требует доказательства принципов (POI: prep-датасет с синтетическими дальними факт-ассоциациями).

режиме «datastore доступен», а НЕ ускоритель обучения; на дорожную карту скорости тренера не влияет.

#### Составляющая с сильным бэкбоном — [измерено] выигрыш схлопывается
Datastore перестроен из ckpt Муon-чемпиона (seed-1, 111.21 PPL full-val; на val-сплите зонда 105.01):
λ* сместился 0.2→0.1, лучший Δ = **−1.1%** (103.90). Сравнение: на adam-бэкбоне (199.26 → 169.25)
было −15.1%. Внешняя память компенсирует НЕДОСТАТОЧНОСТЬ модели, а не добавляет поверх силы —
точное подтверждение урока EXP14 (HDC бесполезна: бэкбон сам до-выводит). Итоговый вердикт
семейства «триггер-память»: жизнеспособна ТОЛЬКО как костыль слабой модели; для чемпионского
рецепта прибавка ~1% при ×1.4–3 latency и +250MB статики — продуктово мертва. Закрыто с
благодарностью за −15%, ставшие мерой недостатка старого бэкбона.
