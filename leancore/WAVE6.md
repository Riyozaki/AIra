## 1. Рычаг 1: sampled softmax (batch-candidates + sampling-bias коррекция)
Формулировка: на шаг выбирается общий набор кандидатов C = targets ∪ K негативов из unigram-предложения
(with replacement); логиты корректируются z_c − log Q_c, **Q_c = 1 − (1 − q_c)^K** — inclusion-вероятность
(sampling-bias-corrected softmax, Blanc–Rendle'20 / RAW, Chen'20 [якоря]; per-example вариант — Jean'15).
Валидация — всегда полный softmax ⇒ метрики сопоставимы с базой.
- Реализация: `nano_lc.py::sampled_ce/sampled_ce_bwd` + разреженный `backward(head_cache=...)`; CLI `--ssk K`, `--ssfull f` (аннилинг хвоста полным CE).
- Ожидание по профилю: −85% стоимости головы (~m/V ≈ 10.2% при K=512: m ≈ 819 из 8000) ⇒ модельный выигрыш ~×1.5 на шаге [проекция из [измерено]-профиля].
- FD-проверка: `sampled_ce` 3.1e-6, `ss+erank` 2.9e-5 [верифицировано].

### 1.1. Инженерные ловушки, найденные на ПУТИ (главный урок волны)
Первый запуск дал всего ×1.05 вместо ×1.5. Разбор (всё [измерено], методика: модель в одном процессе,
режимы интерливнуты, CPU-учёт time.process_time, rusage по секциям):
1. **`np.add.at` — O(элемент) скалярный путь**: emb-scatter 2304 строки × D и head-dEc 819 × D ≈ 50–80 мс/шаг.
   → `scatter_add_rows()` (argsort+reduceat, векторно) и fancy-add по уникальному cand. embscat: 58→7.5 мс.
2. **glibc malloc page-fault шторм**: массивы со СЛУЧАЙНЫМ размером (m плавает 761–854 на шаг) ≥ mmap_threshold
   → mmap/munmap на каждом шаге: +1500 minor faults/шаг против базы (rusage). Лечение env:
   `MALLOC_TRIM_THRESHOLD_=1000000000 MALLOC_MMAP_THRESHOLD_=33554432` (33554432 = жёсткий максимум glibc;
   массивы ss ≤ 19 МБ навсегда оседают в brk). Полный прогон ss: 4580→4984 tok/s только от env (+9%).
   Бонусом baseline тоже ускоряется (+2.7%): флаги прописаны в `bench_ss.sh`.
3. Шум измерений на этом vCPU: wall метрики гуляют ×1.5–2 между минут (перепроданный хост) — все
   A/B выводы только по медианам ×3 повтора + интерлив; CPU-время и minflt как корреляты.

## 3. Рычаг 2: низкоранговый tied-эмбеддинг (--erank r) — [реализовано, FD-верифицировано, A/B идёт]
E(V,D) → U(V,r)@P(r,D): lookup x0=U[ids]@P; голова lg=(H@P.T)@U.T (композиция с ss: кандидаты (B,T,r)@(r,m)).
- Параметры E-слоя: V·D=1.536M → (V+D)·r: r=96 → 0.786M (−49%), r=64 → 0.524M (−66%).
- Голова MAC (инференс): V·D → (D+V)·r ⇒ −49%…−66%; С-движку нужен патч двухступенчатой головы (roadmap).
- init: Var(E_ij)=r·σ⁴=0.02² ⇒ σ=(0.02²/r)^¼; Muon исключает U (как E), P muon-изируется.
- FD: `ema+erank` 8.2e-5, `ss+erank` 2.9e-5 [верифицировано].

у него нет «перехода» — дефицит ранга не компенсируется временем). tok/s в этом прогоне не котируется
(контеншн очереди); скоростной выигрыш erank — инструментальная тема ИНФЕРЕНСА: двухступенчатая
голова `z@Pᵀ (d→r) → U (r→V)` срезает 49–66% стоимости головы при экспорте → T4. Из тренерского
стека как «ускоритель шага» erank снят с повестки (флаг `--erank` оставлен: FD-тест + будущий
экспортный путь). Детали и salvage-вердикты по внешним заброшенным линиям — см. `SALVAGE.md`.
